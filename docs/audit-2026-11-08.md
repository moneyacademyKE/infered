**Audit task:** `bk-d028`

## Verdict

**Score: 58 / 100.**

The repository is small, dependency-free, syntactically healthy, and its streaming design is materially better than a naive proxy. The production evidence is not healthy, though: the latest observed D1 window contains **83 decisions, 27 successes, and 56 non-successes**. That is a 67.5% observed failure/disconnect rate in the window from 2026-11-07 03:00 EAT through 2026-11-08 20:09 EAT. The long historical window remains strong at 20,174 successes out of 20,482 rows (98.5%), so this is a recent incident signal, not a claim that the whole lifetime is broken.

The biggest risk is not module structure. It is the boundary between an unauthenticated public Worker, mutable provider configuration, and a live upstream whose failures can consume 10 attempts and more than two minutes before the client gets a useful answer.

## Severity-ranked findings

### F1 — Critical: public completion and admin surfaces have no application authentication

**Evidence:** `src/worker.js:98-108, 210-212` dispatches requests without checking an incoming client credential. `src/router/telemetry.js:6-11` allows `*` origin and exposes `Authorization`. `/v1/admin/sync` accepts both GET and POST at `src/worker.js:200-207` and has no admin check.

**Why it matters:** anyone who discovers the Worker URL can submit completions against the account-funded upstream, trigger market refreshes, and read operational data. The application currently assumes that possession of the URL is authorization.

**Recommendation:** require a dedicated router credential (or Cloudflare Access) before any chat/admin route. Keep the upstream `INFERHUB_API_KEY` server-only. Remove the fallback that treats the caller's `Authorization` header as an upstream key; a missing server secret must be a 503 configuration error, never a mock-success path or credential relay.

### F2 — High: recent production reliability is unacceptable

**Evidence:** D1 rows from 2026-11-07 03:00 EAT through 2026-11-08 20:09 EAT: 83 total, 27 successful, 44 client disconnects, 11 non-retryable upstream opens, and 1 pre-content exhaustion. Recent attempts include 10 and latency reaches 135,530 ms. All recent rows were recorded as served by `ali/glm-5.3`, including requests for `infered/glm-budget` and the typo-shaped `ali/qwen-3.8-max-0902`.

**Why it matters:** the router can be internally correct while the client still experiences long waits and disconnects. A 30-second pre-commit budget and 10-attempt policy are not enough if the selected model remains congested or if the client timeout is shorter.

**Recommendation:** treat disconnects as a first-class SLO, not as successful routing. Add a bounded end-to-end deadline that includes all candidate attempts, cap attempts according to remaining time, and expose a request-level failure reason plus first-byte/last-byte timings. Investigate why the latest window collapses onto one served model despite a seven-model book.

### F3 — High: request bodies and messages are not bounded or validated

**Evidence:** `src/worker.js:212` calls `request.json()` directly. There is no content-length check, body-size limit, message-count limit, or field/type validation before ranking and upstream serialization. `src/router/session.js:30-42` scans the first user message and accepts up to 512 characters only after the full request has already been parsed.

**Why it matters:** oversized or malformed requests can consume Worker CPU/memory, create enormous upstream payloads, or produce avoidable 500 responses. This is an abuse and stability surface, especially while the endpoint is public.

**Recommendation:** reject oversized bodies before parsing, validate the OpenAI request shape, bound messages/tools/content, and reject non-finite numeric controls. Return 400 with a stable error shape.

### F4 — High: analytics HTML interpolates unescaped data from D1

**Evidence:** `src/ui/analytics.js:125-153` inserts model names, timestamps, chain names, and error strings directly into HTML template strings. Those values originate in routing decisions and upstream error text (`src/router/telemetry.js:50-63`). No HTML escaping function exists.

**Why it matters:** a crafted model name, request value, or upstream error can become stored XSS when an operator visits `/` or `/analytics`. The dashboard is server-rendered and CORS is broad, so this is an operator-facing trust boundary.

**Recommendation:** escape every interpolated value at the render boundary. Add a regression test with `<script>` and attribute-breaking payloads. Do not rely on model catalog validation alone because error text and requested names are not catalog-controlled.

### F5 — High: synthetic market state can present as healthy live state

**Evidence:** `src/worker.js:17` hard-codes a 15-second sync trigger while `wrangler.jsonc:15` declares `PRICE_CACHE_TTL_SEC: "60"`; the variable is never read. `syncLiveInferHubQuotes` swallows all errors at `src/worker.js:65-80`. The live `/v1/health` response reports `cachedQuotes: 21`, seven models, and `lastSyncRaw: null`, while `pricing.js:32-48` seeds synthetic spot quotes.

**Why it matters:** the router can route on seeded asks while health looks healthy, even when the live market sync has never succeeded. That makes capacity failures look like model-selection failures and explains why production can repeatedly choose a seller that is not actually available.

**Recommendation:** distinguish `seeded`, `live`, and `stale` quote state in health and ranking. Make sync failure visible with a timestamp and error class. Read the configured TTL or delete the dead variable; do not keep two policy sources.

### F6 — Medium: configuration and documentation drift can recreate retired behavior

**Evidence:** `.dev.vars.example:3-4` still advertises `sol-budget-cascade` and `MAX_FALLBACK_PRICE=0.10`; `src/dev_server.clj:21` defaults to `api.inferhub.net` while `wrangler.jsonc:8` uses `api.inferhub.dev`. Historical ADRs and scripts still contain retired Sol names and the old budget ladder.

**Why it matters:** a fresh local run or future operator can unknowingly test a different upstream, policy, and model universe from production. This is the same class of drift that previously left the live ceiling at $0.10 while source tests expected $0.50.

**Recommendation:** make one canonical config example match production, remove retired names from active scripts, and add a CI drift check for base URL, policy names, and ceiling declarations.

### F7 — Medium: D1 production schema is not reproducible from the repository

**Evidence:** `wrangler.jsonc:17-23` declares the database binding, and application code assumes `routing_decisions` and `session_pins`, but no migration directory, SQL schema, or migration command is tracked.

**Why it matters:** a new environment cannot be reconstructed safely; schema drift has already caused tooling confusion around timestamp and budget columns. Operators must recover production structure from the live account or memory.

**Recommendation:** add numbered D1 migrations and a read-only schema check to CI/deploy verification. Keep schema changes separate from application deploys and record the expected columns in tests.

### F8 — Medium: fallback failure telemetry undercounts work

**Evidence:** `src/router/client.js:247-275` adds primary attempts to `result.attempts` only when the fallback succeeds. If both primary and fallback fail, the fallback result replaces the primary result without summing attempts or preserving both error sets.

**Why it matters:** failed requests can appear cheaper and shorter than they were. That corrupts the exact evidence needed to explain instability and makes attempt caps/SLOs look better than reality.

**Recommendation:** merge attempts and `failoverErrors` on every chain-fallback outcome, success or failure, and add a test for primary-fail plus fallback-fail.

### F9 — Medium: deterministic response cache keys are incomplete and collision-prone

**Evidence:** `src/router/cache.js:20-36` keys only model, messages, temperature, top_p, and tools, then uses a 32-bit signed hash plus string length. It omits fields such as `max_tokens`, penalties, seed, response format, tool choice, and other completion controls.

**Why it matters:** two materially different deterministic requests can share a cache entry and receive the wrong answer. A 32-bit hash is also a weak collision boundary for a long-lived in-memory cache.

**Recommendation:** canonicalize the complete supported request shape and use a collision-resistant digest or a collision-verifying stored payload. Keep caching opt-in until the key contract is complete.

### F10 — Medium: stream classification is heuristic rather than protocol-aware

**Evidence:** `src/router/stream.js:43-52, 318-341` detects content with the exact string `"content":"` and errors with the exact substring `{"error":{`. Whitespace, field ordering, alternate valid JSON formatting, or provider-specific SSE frames can bypass classification. The module is already 454 lines and close to the hard 500-line ceiling.

**Why it matters:** the code can falsely classify a live answer as empty or relay a provider error as successful content. The most important stability boundary is implemented with string needles instead of parsed SSE event data.

**Recommendation:** split the parser at the natural seam, parse each bounded SSE event structurally, and keep the splice state machine small. Add fixtures for whitespace, split UTF-8, provider error variants, empty content, and post-content truncation.

### F11 — Medium: operational credential handling is unsafe even without a committed secret

**Evidence:** `scripts/d1-stress-window.bb:7-25` reads Cloudflare credentials from `~/.zsh_history`. `.dev.vars` is ignored but has mode `0644`, so local credentials are world-readable to other local users.

**Why it matters:** shell history and broadly readable dotenv files are poor secret stores. A history leak or local account boundary failure exposes the D1 account key.

**Recommendation:** use an authenticated Wrangler profile or environment injection from a secret manager; never parse shell history. Change local secret files to `0600` and add a setup check that refuses weaker permissions.

### F12 — Medium: no automated integration gate protects the deployment path

**Evidence:** no `.github/workflows` or other CI configuration exists. The repository relies on a local Babashka runner and manual Wrangler deployment. `git log` shows 66 commits and `main` is four commits ahead of `origin/main`; there is no visible release/deployment receipt in the Worker health response.

**Why it matters:** a green local suite can diverge from production configuration, D1 schema, or the deployed revision. The previous ceiling incident is exactly what a config-aware CI/deploy gate should catch.

**Recommendation:** add a minimal CI workflow for syntax, `bb test-all`, `bb lint`, config drift, secret scanning, and a post-deploy smoke test. Expose a non-secret build revision in `/v1/health`.

## Healthy patterns worth preserving

- Zero runtime dependencies and a small, compositional module graph.
- All production modules are below the 500-line ceiling; `worker.js` is 393 lines.
- The test runner covers 11 namespaces and the suite stayed green across three consecutive runs.
- Streaming explicitly propagates client aborts, bounds first-byte/pre-commit waits, classifies pre-content failures, and synthesizes a terminal sentinel where possible.
- Pricing uses stable price-derived node IDs and evicts stale InferHub nodes rather than retaining ghosts.
- D1 writes are asynchronous and deliberately prevented from breaking the request path.
- No committed credential value was found in the bounded repository scan.
- The live model surface is the intended five virtual chains, not the retired model zoo.

## Recommended order

### P0 — before calling the service stable

1. Add router authentication and lock `/v1/admin/sync`; stop relaying caller credentials.
2. Add request size/schema limits and reject invalid numeric policy inputs.
3. Explain and reduce the current D1 failure window: 56 non-successes of 83 observations, with 10 attempts and 135.5-second latency recorded.
4. Make health distinguish live market sync from seeded fallback state.

### P1 — next change set

1. Escape analytics HTML and add stored-XSS regression tests.
2. Merge all chain-fallback attempts/errors into telemetry.
3. Add D1 migrations and a schema verification command.
4. Remove stale config examples/scripts and read the TTL from one source.
5. Add CI and a post-deploy revision/smoke check.

### P2 — deliberate cleanup

1. Replace heuristic SSE string scanning with a bounded event parser.
2. Correct or disable the response cache until its key covers the supported request contract.
3. Delete the write-only metrics history and label isolate-local metrics honestly.

## Rich Hickey certification

The architecture's core is worth keeping: data catalog → eligibility → execution → evidence. The audit's recommendation is not a platform rewrite. It is to remove the complecting seams that make a small router lie: public trust mixed with upstream credentials, seeded quotes mixed with live quotes, HTML mixed with raw data, and fallback attempts mixed with incomplete telemetry. Fix those boundaries and delete the dead operational paths; do not add a framework to hide them.
